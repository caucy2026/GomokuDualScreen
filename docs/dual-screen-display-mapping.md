# KEMI 双屏对战适配（4.6）

本次规则来自用户指定的 `kemi-dual-battle-display/SKILL.md`，物理屏身份与交换语义来自
`vendor/newlink/development/docs/AI双屏助手产品形态与软件状态说明.md` 第七章。

物理屏 A 固定黑方，物理屏 B 固定白方；系统主副屏角色不决定阵营。

## 映射：由固件状态算出，不做现场标定

固件说明写明了硬件与逻辑角色的关系：

| 状态 | 逻辑主屏（`displayId=0`） | 逻辑副屏（另一块） |
| --- | --- | --- |
| 交换关闭 `master=0` | 显示在物理屏 **A** | 显示在物理屏 **B** |
| 交换开启 `master=1` | 显示在物理屏 **B** | 显示在物理屏 **A** |

物理屏 A = 出厂主屏（MIPI 转 eDP），物理屏 B = 出厂副屏（HDMI 转 eDP）；交换只换逻辑角色，
两侧面板的硬件身份不变。因此：

```text
黑方（物理屏 A） = master == "0" ? 逻辑主屏 : 逻辑副屏
白方（物理屏 B） = master == "0" ? 逻辑副屏 : 逻辑主屏
```

逻辑副屏按实际显示列表取（排除虚拟屏与 `STATE_OFF`），不写死 `displayId=2`。
实现见 `PanelMap.kt`，用例见 `PanelMapTest.kt`。

## 方向：黑方 0°，白方 180°

面对面时两名玩家坐在设备两侧：白方坐在黑方对面，看到的“上”与黑方相反。固件的普通展开补偿只保证
**同一观看者**看到正向，不会替对战应用把另一面转成对面视角，所以白方内容必须在自己的窗口里再转 180°：

| 玩家 | 物理屏 | 内容旋转 |
| --- | --- | --- |
| 黑方 | A | 0° |
| 白方 | B | 180° |

旋转施加在内容根 View 上，`ViewGroup` 会把逆变换套到触摸事件上，落子坐标不需要另行换算；
弹窗、提示同属这棵 View 树，跟着一起转。见 `PanelMap.contentRotation`。

注意这层补偿只处理“两名玩家面对面”这一件事，不跟随形态变化叠加：形态切换时系统自己的投影补偿照旧生效，
应用不再额外加第二次翻转。

## 遮罩：只在真未知时出现

保留中性遮罩只有三种情况，出现期间双方都不能落子：

1. `persist.vendor.display.master` 读不到或不是 `0/1`；
2. 可用面板不足两块（一屏 `STATE_OFF`、被移除、只剩虚拟屏）；
3. 两块屏算出同一个 `displayId`。

`vendor.nl.screen_mode` 缺失不再影响开局：它只用于诊断日志，不参与玩家归属判定。

## 切换与恢复

`DisplayManager` 事件 + 每约 100ms 一次的只读属性采样合并驱动检查。状态指纹（交换状态、形态、
各屏 id/state/rotation/名称）变化时旧版本失效：遮罩、对两侧补发 `ACTION_CANCEL`、清预览、
停 AI 与计时；随后按新映射重绑窗口（必要时 `launchDisplayId` 迁移），等两侧各自提交新版本帧
后再解除遮罩、恢复输入。

对局、历史、回合、暂停次数写入 `AtomicFile`；Activity 重建共享内存会话，进程恢复读文件。
任一侧关屏时另一侧进入等待，不切单屏、不判负、不重开。

## 验收

十种稳定摆放场景（5 方位 × 交换开/关，见固件说明第七章第 3 节的表）逐一核对：

- A 屏始终黑方视图、B 屏始终白方视图，没有互换、没有同显；
- 画面完整、文字朝向正确（朝向以人眼观察为准，截图不足以证明）；
- 四角与中心命中正确，两侧同时多指不串玩家；
- 按住期间切换形态，旧手势取消、不误落子；
- 对局不重开，盘面、手数、当前回合保留；
- 快速连续交换/折叠后映射正确，过程中不露出对方私有画面。

另测单侧关屏恢复、后台恢复、杀进程冷启动。

## 构建

JDK 17、Android SDK 34、Gradle wrapper 8.5：

```text
gradlew assembleRelease testDebugUnitTest
```

包 ID 为 `com.gomoku.dualscreen`。发布签名从本机 `local.properties`
（`RELEASE_STORE_FILE` / `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_ALIAS` / `RELEASE_KEY_PASSWORD`）
读取，该文件不入库；正式覆盖升级必须使用原发布签名，不得卸载原包绕过签名不匹配。
