# KEMI 双屏对战适配（4.6）

本次规则来自用户指定的 `kemi-dual-battle-display/SKILL.md`。物理屏 A 固定黑方，物理屏 B 固定白方；系统主副屏角色不决定阵营。原 AGENTS.md 的“Display 0 永远黑方”属于旧版实现，已由本次明确需求替代。

## 映射与方向

| 对象 | 规则 |
| --- | --- |
| 物理屏 A | MainActivity、黑方、基准上边 A |
| 物理屏 B | GamePresentation、白方、基准上边 B |
| 当前输出 | 从当前固件状态对应的标定记录中读取 displayId |
| 方向补偿 | A/B 分别读取标定的 0° 或 180°，施加到整个内容根 View（含弹窗） |
| 触摸 | Android View 分发负责逆变换；不再次手工翻转坐标 |
| 对局 | 一份 GameState.game；落子携带固定玩家，校验回合；显示屏变化不启动新游戏 |

状态键格式为 `master:screen_mode:displayId=rotation,...`，rotation 使用 Android Surface 枚举值（0/1/2/3）。配置绑定 `Build.FINGERPRINT`，两条输出不得指向同一逻辑屏，显示名称也必须匹配。未标定、不完整、属性未知或任意绑定屏关闭时，两侧均显示中性遮罩并停止落子/计时/AI。

不提供未经物理观察的默认交换公式。`displayId`、屏幕名称及截图本身都不能证明物理面板归属。相同状态键如果实测对应不同物理输出，本实现不能区分，需增加固件稳定标识或新的板级信号。

## 真机标定

1. 将设备放在明确的 0° 基准姿态。在两个实体屏上分别贴 A/B 标记，再标记各自画面的上边。
2. 安装测试包，启动五子棋。未标定时，点击任意屏的中性遮罩进入该屏标定页。初次窗口探测仅放置标定入口，不开放游戏权限。
3. 按实体贴纸选择 A（黑方）或 B（白方）。如箭头不对应原来的面板上边，点击“方向补偿 0° / 180°”后保存。分别完成两屏。
4. 两屏匹配当前映射且均提交新版本帧后，自动恢复游戏；从新的 DOWN 开始接受触摸。
5. 真实操作主副屏交换、180° 姿态、A 字形及组合。遇到未标定状态重复步骤 2–3，始终沿用步骤 1 的实体标记。
6. 更换固件后重新标定。不要通过改系统属性或全局旋转代替实体操作。

已标定画面可以点击 `V4.6 · 校准` 重新打开本屏校准页。

配置在应用私有目录 `files/battle-display.json`，可用 `adb shell run-as com.gomoku.dualscreen cat files/battle-display.json` 导出核对。

## 切换与恢复

DisplayManager 事件和每约 100ms 的后台只读属性采样共同驱动映射检查。变化使旧版本失效，发送 CANCEL、清除两侧预览、遮罩游戏，按标定记录重建必要窗口；等待两个新版本帧提交后解除屏障。计时只有 MainActivity 一份，等待期间不递减；AI 回调核对映射版本。

对局、历史、回合、暂停次数、挑衅次数及剩余提醒秒数写入 AtomicFile；Activity 重建共享内存会话，进程恢复读取保存文件。Home 不再直接销毁双方。任意一侧停止显示时，另一侧进入等待，不切换 AI 或单屏模式。

## 验收矩阵

逐项覆盖进入、退出、冷启动：未交换/已交换 × 实际姿态 0°/180° × 非 A 字/A 字。每项检查实体归属、上箭头、四角与中心命中、两侧同时输入、按住中切换、对局不重开以及快速连续切换。

额外检查任一侧关屏/恢复、后台恢复和进程重启。只有包含实体贴纸的观察才能确认最终方向，截图验证只用于布局和逻辑输出。

## 构建

JDK 17、Android SDK 34、Gradle wrapper 8.5：

```text
java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain assembleDebug testDebugUnitTest
```

Debug 与 Release 使用同一个包 ID `com.gomoku.dualscreen`。仓库里机器路径绑定的发布签名配置已移除，正式覆盖升级必须使用原发布签名；不得卸载原包来绕过签名不匹配。
